# База знаний: параллельные живые отчеты Cash / Bank Card

Дата: 2026-05-22
Проект: `finance.brkovic.ltd / FinDesk`
Статус: правило первого этапа внедрения новой финансовой архитектуры

## Главная Идея

`Живой отчет` делится на два независимых потока:

```text
Cash / Наличные
Bank Card / Банковская карта
```

Это не два типа строк внутри одной карточки.

Это два параллельных рабочих процесса с одинаковым UX, разными `id`, разной цветовой темой и разными правилами расчета.

Потоки не смешиваются вообще.

Единственное место пересечения - отдельная ячейка в сводном отчете:

```text
Потрачено с банковской карты
```

## Стартовый Дисклеймер Перед Работой

Перед началом работы в `Живом отчете` пользователь должен явно выбрать режим:

```text
Наличные
Банковская карта
```

Смысл дисклеймера не юридический, а рабочий:

```text
Выберите, чем вы сейчас платите. Наличные и банковская карта считаются отдельно.
```

После выбора пользователь попадает в тот же знакомый интерфейс `Живого отчета`, но уже в выбранном потоке.

## Общий UX Для Двух Потоков

Интерфейс одинаковый:

- список карточек как iPhone Notes;
- открытая карточка как заметка;
- быстрый ввод строк;
- камера;
- скан;
- медиатека;
- сохранить;
- сдать;
- вернуть на исправление;
- архив рабочего экрана.

Разница только в:

- `stream_id` / внутреннем типе потока;
- цветовой гамме;
- расчетной формуле;
- фоновой метафоре;
- месте попадания в сводный отчет.

## Цвет И Визуальная Метафора

### Cash

Цвет:

```text
мягкий зеленоватый оттенок
```

Фоновая метафора в рабочем окне:

```text
пачка купюр / наличные деньги
```

Смысл:

```text
реальные деньги на руках
```

### Bank Card

Цвет:

```text
мягкий желтоватый оттенок
```

Фоновая метафора в рабочем окне:

```text
банковская карта
```

Смысл:

```text
расход с карты без контроля физической кассы
```

## Cash Поток

Cash работает от входящей суммы.

Для администратора:

```text
база = доступная касса администратора
```

Для сотрудника:

```text
база = сумма, выданная сотруднику под отчет
```

Формула:

```text
остаток наличными =
  входящая сумма
  + приход наличными
  - расход наличными
```

Cash-поток отвечает на вопрос:

```text
сколько физически должно быть на руках
```

## Bank Card Поток

Bank Card не имеет входящей суммы.

Он всегда начинается от нуля.

Формула:

```text
карточный итог =
  0
  - расходы с карты
```

В интерфейсе нельзя показывать "остаток карты", если система не подключена к банку.

Правильные формулировки:

```text
Потрачено с карты
Карточные расходы
Карта: -€120.00
```

Неправильные формулировки:

```text
Остаток карты
Касса по карте
Было на карте
```

Bank Card-поток отвечает на вопрос:

```text
сколько расходов оплачено банковской картой
```

## Одинаковое Поведение Для Всех Участников

Правила Bank Card одинаковые:

- для администратора;
- для сотрудника;
- для manager;
- для advanced.

Карта всегда идет отдельным потоком от нуля в минус.

Карта не влияет на:

- физическую кассу администратора;
- физический остаток сотрудника;
- сумму выданного подотчета;
- переход остатка cash-карточки в следующую cash-карточку.

## Подотчеты И Advanced

На первом этапе полностью безналичные переводы, банковские карты сотрудников, компенсации и сложные карточные подотчеты оставляем заглушкой в `Advanced`.

То есть в `advance` пока фиксируем:

```text
Cash-подотчет - полноценный поток
Bank Card-подотчет - единый интерфейс расхода, но без сложной банковской логики
```

Позже можно расширить:

- корпоративные карты;
- личная карта сотрудника с компенсацией;
- банковская выписка;
- импорт транзакций;
- сверка с банком.

Но первый этап не должен ломать главную кассовую модель.

## Сводный Отчет

Cash и Bank Card сходятся только в сводном отчете.

Сводная таблица должна иметь отдельные колонки:

```text
Наличные расходы
Карточные расходы
Всего расходов
Остаток наличными
```

Пример:

```text
Наличные расходы: €150.00
Карточные расходы: €40.00
Всего расходов: €190.00
Остаток наличными: €850.00
```

Карточный расход участвует в общем "потрачено", но не уменьшает "остаток наличными".

## Инварианты Backend

1. `cash` и `card` должны храниться как разные потоки/сессии/карточки.

2. `card`-поток не имеет `cash_received`.

3. `card`-поток не создает и не меняет cash remainder.

4. `card`-поток не влияет на `available_cash_balance`.

5. `card`-поток может попадать в общий отчет только как отдельная сумма карточных расходов.

6. Нельзя смешивать строки `cash_out` и `card_out` в одной расчетной базе остатка.

7. Cash-карточка и Card-карточка могут иметь одинаковый внешний UX, но разные `stream_id`.

8. В архиве и журнале поток должен быть виден явно:

```text
stream_type = cash | card
```

## Первый Этап Внедрения

Цель первого этапа:

```text
перестать считать карту частью кассы
```

Сделать:

1. Перед входом в `Живой отчет` добавить выбор `Наличные / Банковская карта`.

2. Создавать одинаковые карточки под разными потоками.

3. Развести CSS-темы:

```text
cash -> green glass
card -> yellow glass
```

4. В cash-потоке оставить текущую кассовую логику:

```text
было -> расход -> остаток
```

5. В card-потоке сделать логику:

```text
0 -> расход -> итог с минусом
```

6. В FinDesk показывать поток карточки явно, но без перегруза:

```text
Наличные
Карта
```

7. В Advanced и сводке добавить отдельную строку/ячейку:

```text
Потрачено с карты
```

8. Для сложных банковских переводов и полностью безналичных отчетов оставить заглушку в Advanced.

## Техническая Фиксация 2026-05-22

Внедрен базовый развод потоков:

- `on_the_go_tapes.stream_type = cash | card`;
- `cash` карточки используют `cash_in` / `cash_out`;
- `card` карточки используют только `noncash_out`;
- `ql_on_the_go_card_summary()` возвращает отдельные `cash_delta` и `card_delta`;
- `available_cash_balance` берет только `cash_delta`, а не общий `balance_delta`;
- список и новая карточка `Живого отчета` фильтруются по выбранному потоку;
- перед входом в живой отчет добавлен выбор `Наличные / Карта`;
- cash-тема зеленоватая, card-тема желтоватая.

Минимальный инвариант проверки:

```text
card report:
  cash_received = 0
  cash_left = 0
  cash_delta = 0
  card_delta = -card_out
  after_amount = -card_out
```

Это означает: карточный расход виден в общем расходе, но не меняет физическую кассу.

## UX-Формулировка

Короткий текст перед выбором:

```text
Чем платим сейчас?
Наличные и карта считаются отдельно.
```

Кнопки:

```text
Наличные
Карта
```

На мобильном это должен быть быстрый выбор, а не отдельная административная форма.

## Почему Это Важно

Администратор сверяет приложение с реальными деньгами на руках.

Если карточные расходы уменьшают cash-остаток, система начинает показывать красивую, но физически ложную цифру.

Новая архитектура сохраняет простоту:

```text
Наличные: сколько осталось на руках.
Карта: сколько потрачено с карты.
Сводка: общий расход двумя отдельными колонками.
```
