## 1. Цель фазы

Phase 1 была переведена из режима "латать старый экран" в режим функциональной пересборки продукта.

Главная цель:

1. не ломать фундамент;
2. не переписывать базовую финансовую математику;
3. пересобрать пользовательский путь вокруг понятных рабочих экранов;
4. привести `FinDesk` к модели:
   - активная группа;
   - люди как главный экран группы;
   - карточка администратора;
   - карточка сотрудника;
   - живой журнал;
   - сборка общего отчета.

Ориентир фазы:

- `docs/AI_TEAM/51_PHASE1_FUNCTIONAL_BLUEPRINT_MANDATE_2026-06-02.md`
- материалы из Drive-папки, принятой как новый маяк продукта;
- alignment patch на архитектуру `10/10`.

## 2. Что не трогали

Фундамент сознательно не переписывался:

1. авторизация по email + коду;

## 3. Что пересобрано в Phase 1

### 3.1. Live Journal

Экран `Живого журнала` очищен до MVP-ядра:

1. контекст;
2. старт журнала;
3. текущая сумма;
4. feed записей;
5. одно поле ввода в формате `± сумма и заметка`;
6. одна точка входа во вложения;
7. кнопка `Зафиксировать журнал`.

Принятый формат ввода:

```text
-120 Топливо
+500 Получил наличные
-85 Еда
```

Для карточного потока:

```text
-45 Продукты
-120 Заправка
```

### 3.2. Team Workspace

`Team Workspace` приведен к модели `People Screen`.

Основной смысл экрана:

1. список людей;
2. имя;
3. должность;
4. состояние;
5. быстрый вход в карточку роли.

Публичные состояния на этом уровне:

1. `Нет записей`
2. `Живой журнал`
3. `Готов отчет`

Технические состояния вроде `Attached`, `Locked`, `Archived` из первого уровня убраны как смысловые ярлыки.

### 3.3. Карточка администратора

Карточка администратора пересобрана как рабочий центр группы:

1. свой журнал;
2. очередь на проверке;
3. сотрудники;
4. выдача денег;
5. сборка общего отчета;
6. архивные и вторичные действия вынесены из ядра.

### 3.4. Карточка сотрудника

Карточка сотрудника приведена к упрощенному виду:

1. `Имя`
2. `Должность`
3. `Выдано`
4. `Остаток`
5. `Открыть живой журнал`
6. `Мои журналы`

Убрано из верхнего уровня карточки:

1. `Last Fixation`
2. `Delta`
3. `Spent`
4. лишняя аналитика
5. техническая сводка ради сводки

### 3.5. Group Report Assembly

Сборка общего отчета пересобрана как отдельный понятный блок:

1. статус журнала администратора;
2. сколько сотрудников готовы;
3. сколько уже прикреплено;
4. сумма группы;
5. явные действия:
   - сохранить;
   - печать / PDF;
   - отправить;
   - состав.

## 4. Alignment patch: что внедрено

Ниже статус по обязательному alignment patch.

### 4.1. Transfer offer / acceptance flow

Внедрено.

Теперь логика такая:

`Администратор выдал -> Ждет подтверждения -> Сотрудник подтвердил -> Деньги стали активными`

Что сделано:

1. новые выдачи создаются как `pending` без миграции enum;
2. pending хранится совместимым системным маркером в существующей схеме;
3. сотрудник не может пользоваться `Live Journal`, пока выдача не подтверждена;
4. неподтвержденная сумма не попадает в активные totals;
5. администратор может исправить или отменить неподтвержденную выдачу;
6. логируются:
   - выдача;
   - подтверждение;
   - правка;
   - отмена.

API, добавленные под этот слой:

1. `advance_confirm`
2. `advance_update_pending`

Backend-защита:

1. `on_the_go_signed_sync` блокируется до подтверждения;
2. `on_the_go_create` блокируется до подтверждения;
3. `on_the_go_update` блокируется до подтверждения.

### 4.2. Cash / Card separation

Внедрено.

Подтверждено:

1. `Cash` и `Card` идут отдельными потоками;
2. карточный журнал живет отдельно;
3. карточные суммы не смешиваются с наличными на уровне журнала;
4. в итоговых отчетах подписи приведены к виду `Карта / безнал`;
5. warning по карточному балансу не показывается при обычном входе в карточный журнал;
6. warning показывается только если в карточном потоке обнаружен ненулевой ручной стартовый остаток.

### 4.3. Team Workspace = People Screen

Внедрено частично, но уже в правильной модели.

Сделано:

1. главный объект экрана — участник;
2. на карточке участника акцент на имени, роли и состоянии;
3. убраны технические состояния из первого слоя;
4. pending-перевод помечается отдельно, но не подменяет пользовательское состояние.

Что еще можно дожать:

1. еще суше поджать подписи;
2. пройти ручной UX-аудит уже на живом браузере.

### 4.4. Employee Card final layout

Внедрено.

Текущий верх карточки сотрудника:

1. имя;
2. должность;
3. выдано;
4. остаток.

Дальше:

1. действие по журналу;

### 4.5. Live Journal final cleanup

Внедрено.

Главный объект экрана — записи.

На первый экран не тащатся:

1. тяжелые меню;
2. отчеты;
3. дашборды;
4. аналитика;

### 4.6. Final report structure

Внедрено частично в UI и подтверждено в данных.
