# База знаний: UX/CSS правило стеклянного интерфейса

Дата: 2026-05-21
Проект: `finance.brkovic.ltd / FinDesk`
Статус: правило оформления, пока не применять ко всему проекту автоматически

## Суть Правила

Текущий визуальный язык `Живого отчета` считается удачным и фиксируется как будущий эталон для проекта.

Сейчас это правило нужно сохранить в базе знаний. Применять его ко всем экранам проекта начнем позже, отдельным этапом.

Главная идея:

```text
мобильный рабочий инструмент
+ iPhone Notes логика
+ iOS glass стиль
+ профессиональная финансовая ясность
```

Интерфейс должен выглядеть не как черновая веб-форма и не как хаотичная простыня, а как аккуратный продуктовый инструмент.

## Текущий Эталон

Текущий эталон находится в `Живом отчете`:

- список живых отчетов;
- открытая карточка отчета;
- стеклянные блоки;
- мобильная ориентация;
- отдельные пути для desktop / tablet / mobile.

Основные файлы:

```text
public/app.php
public/assets/app.css
public/assets/app.js
```

Основной CSS-блок:

```text

```

Ключевые классы:


## Визуальный Принцип

Стиль: светлый, чистый, стеклянный, с ощущением iOS.

Использовать:

- мягкий светлый фон;
- полупрозрачные белые блоки;
- blur / backdrop-filter;
- тонкие светлые border;
- глубокие, но мягкие тени;
- крупные округлые рабочие зоны;
- аккуратные контрастные цифры;
- минимум прямого текста на кнопках;
- подсказки через `title` / `aria-label`, где это уместно.

Не использовать:

- тяжелые темные панели;
- плоскую табличную простыню;
- случайные карточки разного стиля;
- вложенные карточки внутри карточек без причины;
- большие маркетинговые тексты внутри рабочего инструмента;
- визуальный шум;
- разные кнопки одного уровня с разной высотой и весом.

## Glass Блоки

Рабочие блоки должны выглядеть как мягкое стекло:

```text
background:
  linear-gradient(145deg, rgba(255,255,255,.86), rgba(255,255,255,.58)),
  rgba(255,255,255,.66);

border:
  1px solid rgba(255,255,255,.80);

box-shadow:
  0 18px 48px rgba(31,41,55,.08),
  inset 0 1px 0 rgba(255,255,255,.64);

backdrop-filter:
  blur(26px) saturate(1.18);
```

Это не обязательный буквальный код для каждого экрана, но это визуальный ориентир.

## Цвета

Базовая палитра:

- фон: очень светлый холодный серо-голубой;
- блоки: белый / полупрозрачный;
- основной текст: почти черный `#0f1724` / `#111827`;
- вторичный текст: серый `#64748b`, `#8b93a1`;
- основной action: системный синий;
- подтверждение / FinDesk-ready: зеленый;
- удаление / ошибка: мягкий красный.

Не превращать проект в одноцветную синюю или фиолетовую тему.

## Кнопки И Действия

Кнопки одного уровня должны быть уравновешены:

- одинаковая высота;
- одинаковый радиус;
- одинаковая плотность;
- понятный приоритет.

Для основных рабочих команд:

```text
Сохранить -> primary blue
Список -> neutral
FinDesk / принять -> soft green
Удалить -> soft red
```

Где возможно, прямой текст сокращать.

На desktop можно показывать больше текста.

На mobile:

- использовать короткие подписи;
- использовать `aria-label`;
- использовать `title` для desktop hover;
- для неизвестных иконок позже добавить нативную/кастомную подсказку по long press или отдельный help-state.

## Разметка По Устройствам

Это обязательное правило для будущего расширения на весь проект.

Нельзя делать один растянутый desktop-layout и пытаться ужать его на телефон.

Нужно иметь три явных пути.

### Mobile

```text
max-width: 700px
```

Мобильная версия является главной для `Живого отчета`, потому что люди работают с ним на ходу.

Правила:

- один экран = одна задача;
- список отчетов отдельно;
- открытая карточка отдельно;
- крупные tap targets;
- без FinDesk-кнопки для base-сотрудника;
- без перегруженного текста;
- блоки идут вертикально;
- textarea занимает ощутимую высоту;
- камера / скан / медиатека доступны рядом с записью.

### Tablet

```text
701px - 1099px
```

Планшет может использовать две колонки:

- основная рабочая область;
- боковая колонка с вложениями, итогами и действиями.

Но логика остается мобильной:

```text
список -> открытая карточка -> назад
```

### Desktop

```text
1100px+
```

Desktop не должен растягивать рабочий экран на всю ширину.

Нужен центральный рабочий canvas:

- общая стеклянная рамка;
- отдельная карточка header;
- ограниченная ширина списка;
- ограниченная ширина редактора;
- свободное поле вокруг;
- без ощущения пустой размазанной страницы.

## Список Как iPhone Notes

Страница списка должна ощущаться как список заметок:

- крупный заголовок;
- дата / группа карточек;
- понятные строки-карточки;
- вся карточка нажимается;
- действия не мешают нажатию по карточке;
- `+` создает новую запись;
- назад возвращает в предыдущий рабочий контекст.

Не делать список как dashboard.

Не делать список как таблицу.

Не делать карточки слишком декоративными.

## Открытая Карточка

Открытая карточка должна ощущаться как открытая заметка:

- header сверху;
- рабочие записи в центре;
- касса / выдано сверху отдельным блоком;
- вложения и итоги отдельными стеклянными блоками;
- действия в отдельной зоне;
- в view-mode показывать карандаш для начала редактирования;
- при редактировании открывать исходные строки, а не пустую карточку.

## Текст И Подсказки

Подсказки должны быть бледнее реального текста.

Placeholder в textarea не должен выглядеть как уже введенные записи.

Технические названия не выводить пользователю.

Плохо:

```text
1 карточка
on_the_go_tape
signed_sync
```

Хорошо:

```text
Журнал
Живые отчеты
Черновик
На проверке
Сохранить
Список
```

## CSS Правило

Когда будем применять стиль шире по проекту:

- сначала выделить дизайн-токены;
- затем переносить паттерны экранами;
- не накидывать новые слои CSS поверх старых;
- удалять конфликтующие старые стили перед заменой;
- не смешивать разные подходы в одном модуле.

Правило:

```text
один экран -> один владеющий CSS-блок -> понятные responsive-ветки
```

Для нового оформления использовать структуру:

```text
base styles
mobile styles
tablet styles
desktop styles
```

## Что Не Делать Сейчас

Сейчас не применять это автоматически ко всему проекту.

Не переписывать Advanced, FinDesk, Groups, Ledger и Premium только ради внешнего единообразия.

Сначала нужно стабилизировать логику `Живого отчета`, подотчетов, групп и общих отчетов.

После этого можно отдельным этапом переносить этот визуальный язык на остальные модули.

## Короткая Формула

```text
Сначала правильный поток.
Потом чистая разметка.
Потом единый стеклянный стиль.
Потом распространение на весь продукт.
```
